# Seasonal Anime Guide

## إعداد الموسم والثيم

ملف إعداد الموقع: `src/data/site-config.json`

- `activeSeason`: الموسم النشط (`winter`, `spring`, `summer`, `fall`)
- `seasons.*`: عناوين، وصف، هاشتاقات، نصوص المشاركة، وثيم الألوان لكل موسم

لتغيير الموقع من شتاء إلى صيف مثلًا:
1. عدّل `activeSeason` إلى `summer`
2. عدّل بيانات الموسم في `seasons.summer` (السنة، العناوين، الهاشتاقات، الألوان)
3. حدّث `data/anime.xlsx` ببيانات الموسم
4. شغّل `npm run build:data`

## Top 5 سوايب

ملف `src/data/top5.json` يتحكم في قسم Top 5. عدّل المصفوفة `titles` بعناوين الأنمي كما هي مكتوبة في `title` داخل بيانات الأنميات.

```json
{
  "titles": [
    "اسم الأنمي 1",
    "اسم الأنمي 2"
  ]
}
```

مصدر البيانات الأساسي الآن هو ملف Excel داخل المستودع:

- `data/anime.xlsx` — بيانات الموقع الحالية
- `data/anime-template.xlsx` — ملف فارغ بنفس الأعمدة المستخدمة داخل الموقع

عند تعديل الملف، يمكن توليد بيانات الموقع JSON محليًا بالأمر:

```bash
npm run build:data
```

أثناء النشر على GitHub Pages، يقوم workflow بتشغيل نفس الخطوة تلقائيًا قبل build، لذلك تعديل `data/anime.xlsx` داخل GitHub يكفي لتحديث القوائم بعد نجاح الـ workflow.

- السكربت: `scripts/build_anime_data.py`
- الملف المولد: `src/data/anime.json`
- الأعمدة المستخدمة داخل الموقع: `اسم الأنمي`, `موعد الإصدار المتحقق` (أو `موعد العرض`), `نوع الإصدار`, `التصنيفات`, `النبذة`, `رابط الصورة`
- أعمدة إضافية مقبولة ويتم تجاهلها حاليًا: `م`, `حالة الموعد`, `درجة التأكد`, `مصدر العمل`, `تفاصيل العرض الأصلية`, `الحلقات`, `صيغة العرض`, `ملاحظات التحقق`, `مصدر التحقق`, `طبيعة النبذة`
- عمود `رابط الصورة` اختياري؛ عند وجود رابط صورة صالح سيظهر كخلفية لكرت الأنمي مع طبقة تعتيم للحفاظ على وضوح النص.
